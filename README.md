## Title: Why are we here?

### Subtitle_1: My Background and How I Use AI

Before coming to Hong Kong Polytechnic University, I was a 3D concept artist, usually using Blender and Photoshop to create concept art.

As a designer, the question I get asked most often is, "AI can already create 3D models, generate images and write code, so why do we need to learn new skills? If AI can do everything in the future, isn't learning these skills a waste of time?" Regarding this question, I agree that AI can help us do many things, including things that were previously beyond our abilities or required extensive practice. However, if a design relies solely on an idea, with everything else handled by AI, then who ultimately owns the resulting work? This is also why I'm in the SD5913 course. I don't just want to learn programming or simply understand the code written by AI. I want to find the answer to this question: if AI can replace humans in doing anything in the future, how will we differentiate ourselves from others?

For me, AI has never played a design role in my workflow. I never use AI to generate models or entire concept sketches. This is because I believe that if I use AI to do these things during practice, I won't be able to develop my ability to create things independently without AI. In my workflow, I only use AI to create plugins that allow me to quickly build concepts and 3D scenes. The two plugins I've included in this repository illustrate this process: I tell the AI what I need, it breaks down the functionality and writes the code, and then I test the plugins and provide feedback. This not only allows me to quickly build concepts but also speeds up my workflow when creating scenes in the same style.

I still consider myself the author of concept art created in this way because I create all the artwork and models myself. However, regarding the plugins, when I share them with others, I don't consider the AI-generated code my own work. I always declare that my contribution to these plugins is limited to defining requirements and testing.

### Subtitle_2: My Goals for the Course

For this course, I believe what I need to learn shouldn't be limited to understanding code or using web scraping tools to download data, although those are necessary. What I really want to learn is how to formulate requirements more efficiently and how to determine whether a particular implementation can be simplified.

Why do I want to learn this? Because I once saw a workshop by Embark Studios at NDC, where they presented their work on ARC Raiders (NDC, 2026). Their tools and methods were incredibly efficient. They used Blender to create the basic shapes and damaged areas (marking the damaged and protected parts with different materials), and then used custom plugins in Houdini to generate the details (Strazd, 2026). Their procedural modeling approach really impressed me. This efficient workflow not only speeds up the construction of game scenes but also ensures that the game's concept design remains consistent throughout.

Their workflow demonstrates their deep understanding of 3D models, textures, and code. They've incorporated the style of a project and the experience of an artist into a tool that can be repeatedly used in subsequent creations. My ultimate goal is to use the code and AI applications taught in this course to build a similar workflow of my own and speed up my scene creation process.

### Conclusion

Ultimately, I hope this course will help me translate my experience as a 3D artist into tools that support my design approach. My contribution should extend from defining requirements and testing results to understanding, simplifying, and adapting the tools themselves. Artificial intelligence can help me realize an idea, but I still need to decide which problems are worth solving and what solutions are suitable for my work. I cannot predict what AI will ultimately achieve. But I can develop my own methods for creating scenes, which will gradually take shape through practice and experimentation. That's why I'm here: to better develop this approach and the tools that make it possible.
